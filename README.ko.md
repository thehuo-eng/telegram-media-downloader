# Telegram 파일 자동 분류 3.1.0-smart

**기본 실행에는 API 키와 Telegram 로그인이 필요하지 않습니다.** Telegram Desktop에서 내려받은 파일을 원본 폴더에서 읽어, 파일명 키워드와 확장자에 따라 원하는 폴더로 복사하거나 이동합니다.

## 1. Telegram에서 PDF 내려받기

Telegram Desktop의 해당 채팅방에서 **⋮ → 대화 내용 내보내기**를 엽니다.

1. **파일**을 체크합니다. PDF만 필요하면 사진·영상 등은 해제합니다.
2. **크기 제한** 슬라이더를 오른쪽으로 올립니다. **8MB / 4000MB는 파일 한 개당 제한이며, 전체 용량이나 파일 개수 제한이 아닙니다.** 100MB PDF를 받으려면 100MB보다 충분히 크게 설정하세요. 사용 중인 화면의 4000MB 설정이면 100MB 파일은 이 크기 제한 때문에 제외되지 않습니다.
3. **경로**를 눌러 충분한 공간이 있는 드라이브의 원본 폴더를 지정합니다. 예: `D:\Telegram원본`.
4. 기간을 확인하고 **내보내기**를 누른 다음, 완료될 때까지 기다립니다.

공식 근거: [Telegram 내보내기 안내](https://telegram.org/blog/export-and-more), [파일별 크기 제한을 설명하는 Takeout 문서](https://core.telegram.org/api/takeout). 접근 제한이나 서버의 내보내기 대기 규칙은 공식 앱을 따릅니다.

HTML과 JSON 중 어느 포맷이어도 이 프로그램은 실제 내려받은 파일 폴더를 읽습니다. 미디어를 포함하지 않은 HTML/JSON만 저장하면 PDF를 분류할 수 없습니다. 크기 제한 때문에 누락된 파일은 이 프로그램이 다시 받지 않으므로 내보내기 설정을 바꿔 내려받아야 합니다.

**용량 예시:** 파일당 100MB가 20,000개라면 원본만 약 **2TB**입니다. 실제 크기의 합계와 파일시스템 공간이 필요합니다. 2TB 드라이브 하나를 꽉 채우기보다 여유 공간을 두세요. 한 번에 받기 어렵다면 Telegram 내보내기의 기간을 나누어 처리할 수 있습니다.

## 2. 실행하고 원본 폴더 읽기

`dist/TelegramFileOrganizer.exe`를 실행합니다. Python 설치, API 발급, Telegram 로그인 없이 로컬 파일 모드가 열립니다. 예전 `TelegramSmartDownloader.exe`는 이전 API 버전이므로 새 파일을 사용하세요.

**1. 원본 폴더 → 원본 폴더 추가 → 폴더 읽기** 순서로 진행합니다. 내보낸 최상위 폴더를 고르고 **하위 폴더 포함**을 켜면 `files` 등의 하위 폴더도 읽습니다. 여러 원본 폴더를 추가할 수 있고, 읽기를 취소해도 이미 수집한 목록은 보존됩니다.

기본 형식은 **PDF만**입니다. 파일 수에 인위적인 제한을 두지 않습니다. 파일 본문을 한꺼번에 메모리에 올리지 않으며 읽기·해시·복사 작업은 GUI 밖에서 실행합니다. `.part`, `.tmp`, `.crdownload` 등 미완료 파일과 링크·정션 하위 폴더는 제외합니다. 원본이 미리보기 이후 바뀌면 처리하지 않고 폴더를 다시 읽도록 안내합니다.

## 3. 범주와 저장 폴더 설정

**3. 범주 · 키워드 → 범주 추가**에서 다음 항목을 입력하고 **범주 변경 저장**을 누릅니다.

| 범주 | 키워드 예시 | 확장자 조건 | 저장 폴더 예시 |
|---|---|---|---|
| 회로이론 | 회로, circuit, ch09 | pdf | `D:\공부자료\회로이론` |
| 전자기학 | 전자기학, electromagnetics, ampere | pdf | `D:\공부자료\전자기학` |
| 강의영상 | 비워 두기 | mp4, mkv, avi | `E:\강의영상` |

- 키워드는 쉼표나 줄바꿈으로 구분합니다. 하나만 포함되어도 일치하며, 대소문자를 무시하고 Unicode를 정규화합니다.
- 키워드와 확장자를 함께 지정하면 두 조건을 모두 만족해야 합니다.
- 우선순위는 위쪽이 높습니다. **↑ / ↓**로 바꿀 수 있고 미리보기에 충돌 규칙이 표시됩니다.
- 분류 순서: **파일별 수동 지정 → 키워드 → 확장자 전용 범주 → 기본 범주 → 미분류 폴더**.
- 기본 범주는 하나만 활성화하며 키워드·확장자를 비웁니다. 규칙 테스트 칸에서 파일명을 직접 확인할 수 있습니다.
- **5. 설정 · 중복 검사**에서 미분류 폴더와 추가로 중복을 검사할 보관 폴더를 지정합니다.
- 원본 폴더와 저장·추가 보관 폴더는 서로 같거나 상하위 관계가 되지 않게 지정하세요. 예를 들어 원본 `D:\Telegram원본`, 저장 `D:\공부자료`처럼 나눕니다.

범주와 저장 경로·수동 분류·선택 상태는 SQLite에 저장됩니다. 범주를 지워도 기존 파일은 삭제하지 않습니다.

## 4. 미리보기 후 복사 또는 이동

**2. 파일 · 분류 미리보기**에서 형식 필터, 검색, 파일 체크와 수동 분류를 적용합니다. **범주 셀을 두 번 클릭**하면 특정 파일의 범주를 바꿀 수 있고 저장 경로가 즉시 갱신됩니다. 전체 다운로드 형식과 범주별 확장자 조건은 별개입니다.

표에는 원본 이름·폴더, 크기, 적용 범주·규칙·충돌, 저장 폴더, 중복 확인 상태와 예상 경로가 나옵니다. 가로 스크롤과 열 정렬을 지원하고, 잘린 셀은 마우스를 올려 전체 내용을 확인합니다.

**체크한 파일 분류 시작**을 누르면 검색으로 숨겨진 체크도 포함됩니다. 검색 결과만 처리하려면 기존 선택을 해제한 뒤 표시된 파일만 선택하세요. 형식 필터로 제외한 파일은 처리하지 않습니다.

| 저장 방식 | 원본 | 필요 공간 및 주의점 |
|---|---|---|
| **복사 — 원본 보존** (기본) | 그대로 유지 | 중복을 제외한 새 파일만큼 추가 공간이 필요합니다. 원본 2TB를 전부 복사하면 최종 보관 공간도 약 2TB가 추가됩니다. |
| **이동 — 저장 완료 후 원본 제거** | 성공적으로 옮긴 파일만 원본 위치에서 제거 | 같은 드라이브에서는 검증 후 이름·위치를 변경하여 전체 사본을 추가로 만들지 않습니다. 다른 드라이브에서는 복사·검증 완료 후 원본을 제거합니다. |

이동은 버튼을 누른 뒤 대상 개수·용량·원본 폴더를 확인하고 승인해야 시작합니다. 이동하면 원래 내보내기 HTML의 파일 링크가 끊길 수 있습니다. **중복으로 판정된 원본은 이동 모드에서도 삭제하지 않습니다.** 따라서 결과 폴더에 중복 사본을 추가하지 않지만, 원본 폴더의 기존 중복을 자동 정리하는 기능은 아닙니다.

## 5. 중복 검사와 파일 보존

- 분류 시작 전에 모든 범주·미분류·추가 보관 폴더의 기존 파일 목록을 자동 인덱싱합니다. 별도 **기존 파일 인덱싱** 버튼도 사용할 수 있습니다.
- 파일 크기로 후보를 먼저 좁힌 뒤 SHA-256으로 실제 내용을 비교합니다. 파일명을 달리해도 내용이 같으면 새 사본을 저장하지 않습니다.
- 같은 이름인데 내용이 다르거나 빈 파일이 이미 있으면 `파일명 (2).pdf`처럼 다른 이름을 사용합니다. 기존 파일을 덮어쓰지 않습니다.
- 원본 폴더의 파일 자체를 저장 완료 사본으로 잘못 간주하지 않습니다. 중복은 보관된 실제 파일을 확인합니다.
- 미리보기에서 내용 검사를 하지 않은 파일은 **미확인**으로 표시합니다. 완료 후 실제 경로·해시·중복 사유가 이력에 남습니다.
- 이미 저장된 파일을 다른 프로그램으로 수정·삭제했다면 실제 상태를 다시 검사합니다. 보관 폴더에 파일을 추가한 경우 다음 시작의 인덱싱에 반영됩니다.

## 6. 중단·재개와 오류 복구

**4. 대기열 · 완료 파일**에서 전체 일시정지, 대기/일시정지 재개, 실패 파일 재시도, 저장 폴더 열기를 사용합니다. 처리 단위는 파일이며 진행률·크기·속도와 이번 작업의 처리 개수를 표시합니다.

복사 중단 시 목적 폴더의 `.tsd-staging`에 임시 파일을 유지합니다. 재개할 때 임시 파일의 앞부분을 원본과 비교해 손상된 부분부터 복구합니다. 저장 직후 종료되더라도 기록한 최종 경로와 SHA-256으로 완료 상태를 복원합니다. 이동 성공 후 원본 제거가 실패하거나 그 전에 종료되면 안전을 위해 원본이 남을 수 있습니다.

원본이 내보내기 중이거나 변경·삭제됐다면 완료된 뒤 폴더를 다시 읽으세요. 여유 공간·폴더 접근 오류는 대기열에 표시됩니다. 규칙을 바꿔도 이미 큐에 넣은 작업은 당시 경로와 복사/이동 선택을 유지하며, 다시 선택해 넣어야 새 규칙이 적용됩니다.

실행 중 `.tsd-staging`, DB 또는 원본 폴더를 수동으로 수정하지 마세요. 완료 파일의 범주를 바꾸는 것만으로 기존 파일이 다시 이동되지는 않습니다.

## 데이터·호환성

- 데이터: `%LOCALAPPDATA%\TelegramSmartDownloader`. 기존 EXE 옆에 `downloader.db`가 있으면 기존 휴대용 위치를 유지합니다. 개발 실행은 저장소 루트이며 `TSD_DATA_DIR`로 별도 지정할 수 있습니다.
- 기존 범주와 SQLite 테이블을 보존하고 `smart_local_files`만 추가합니다. 로컬 이력은 Telegram 계정 이력과 구별하며 PDF 기본 필터도 별도 저장합니다.
- 같은 데이터 폴더로 동시에 두 프로그램을 실행하지 않도록 잠급니다.
- 사용자 파일·DB·인증 정보를 외부 서버로 업로드하지 않습니다. 기본 로컬 모드는 `.env` 인증 정보를 불러오거나 Telegram 클라이언트를 시작하지 않습니다.
- 이전 API 기능이 필요하면 `TelegramFileOrganizer.exe --telegram-api` 또는 `python src/gui.py --telegram-api`로 명시적으로 실행할 수 있습니다. 이 선택 모드에는 본인 API ID·Hash와 Telegram 인증이 필요합니다.
- 원본 [vinodkr494/telegram-media-downloader](https://github.com/vinodkr494/telegram-media-downloader)의 MIT 라이선스와 저작권을 [LICENSE](LICENSE)에 유지합니다.

## 개발 실행·Windows 빌드

Python 3.12 64비트 환경에서 저장소 루트에서 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\run_windows.ps1
.\build_windows.ps1
```

빌드는 자동 테스트 → PyInstaller → 실제 EXE 오프라인 GUI 검증을 수행하고 `dist/TelegramFileOrganizer.exe`를 만듭니다. 별도 검증은 `.\tools\verify_exe.ps1`입니다. 이미 의존성이 준비돼 있으면 `-SkipInstall`, 별도 테스트를 마쳤으면 `-SkipTests`를 빌드 스크립트에 지정할 수 있습니다.

[검증 보고서](docs/VALIDATION.md)와 [구조·테스트 대응표](docs/SMART_ARCHITECTURE.md)를 참고하세요. 실제 2TB/2만 개 PDF의 전체 처리 시간, 다른 Windows PC, 실제 다른 드라이브 이동과 디지털 서명 배포는 별도 확인 대상입니다. 사용자의 실제 자료를 임의로 읽거나 이동하여 시험하지 않았습니다.
