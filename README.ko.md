# Telegram Smart Downloader 3.0.0-smart

파일명 키워드와 확장자로 텔레그램 파일을 자동 분류하고, 지정한 Windows 폴더에 중복 사본 없이 저장하는 PySide6 프로그램입니다.

원본은 [vinodkr494/telegram-media-downloader](https://github.com/vinodkr494/telegram-media-downloader) v2.8.6 계열(기준 커밋 `671d91526cd7d9a0dee6fef1d644f30a47b30797`)입니다. 원본 MIT 라이선스와 저작권 고지는 [LICENSE](LICENSE)에 유지합니다. 기존 로그인·프록시·다운로드 엔진·기존 화면을 재사용하며, 기본 작업 화면으로 한국어 **스마트** 기능을 추가했습니다.

## 실행

- Windows 실행 파일: `dist/TelegramSmartDownloader.exe`를 실행합니다. Python 설치 없이 사용할 수 있습니다.
- 개발 환경: Python **3.12 64비트**에서 다음 명령을 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe src\gui.py
```

이미 가상환경이 있으면 `run_windows.ps1`로 실행할 수 있습니다. 프로그램을 처음 실행할 때 인증 정보가 없으면 로그인 화면이 나타납니다. 왼쪽 **스마트** 버튼으로 로그인 전에도 범주·저장 폴더를 설정할 수 있습니다.

## 처음 로그인하기

1. 본인의 [Telegram API 개발 도구](https://my.telegram.org/apps)에서 API ID와 API Hash를 발급받습니다.
2. **텔레그램 연결**에서 API ID, API Hash, 국제 형식 전화번호를 입력합니다. 한국 번호의 예는 `+821012345678`입니다.
3. **인증 코드 받기**를 누르고 본인의 Telegram 앱에 도착한 코드를 입력합니다.
4. 계정에 2단계 인증이 설정되어 있다면 비밀번호를 입력합니다.

인증 코드·비밀번호·API Hash를 GitHub나 채팅에 올리지 마세요. 프로그램은 Telegram API에 직접 연결하며 사용자 파일을 다른 서버에 업로드하지 않습니다. API 정보는 로컬 `.env`, 로그인 세션은 `.session`에 저장합니다. 2단계 인증 비밀번호와 인증 코드는 설정 파일에 저장하지 않습니다.

## 권장 사용 순서

### 1. 범주와 폴더 만들기

**3. 범주 · 키워드 → 범주 추가**에서 이름, 키워드, 확장자 조건, 저장 폴더를 입력하고 **범주 변경 저장**을 누릅니다. 키워드는 줄바꿈 또는 쉼표로 구분합니다. 항목 수에 프로그램이 정한 제한은 없습니다.

| 범주 | 키워드 | 확장자 조건 | 저장 폴더 예시 |
|---|---|---|---|
| 회로이론 | 회로, circuit, ch09 | 비워 두기 | `D:\공부자료\회로이론` |
| 전자기학 | 전자기학, electromagnetics, ampere | 비워 두기 | `D:\공부자료\전자기학` |
| 강의영상 | 비워 두기 | mp4, mkv, avi | `E:\강의영상` |

- 키워드는 하나만 포함되어도 일치합니다. 영문 대소문자를 무시하고 Unicode를 정규화합니다.
- 키워드와 확장자를 함께 지정하면 두 조건을 모두 충족해야 합니다.
- 키워드 없이 확장자만 지정한 범주는 형식별 기본 범주입니다.
- 위쪽 범주가 우선이며 **↑ / ↓**로 순서를 바꿉니다. 충돌한 다른 범주는 미리보기의 규칙 열에 표시합니다.
- 전체 기본 범주는 활성화된 항목 하나만 지정할 수 있고, 키워드와 확장자는 비워 둡니다.
- 분류 순서는 **파일별 수동 지정 → 키워드 → 확장자 전용 범주 → 기본 범주 → 미분류 폴더**입니다.
- **저장된 규칙 테스트**에 파일명을 입력하면 범주와 경로를 바로 확인합니다. 이 테스트는 범주 규칙만 검사하며 전체 다운로드 형식 필터는 적용하지 않습니다.
- 범주 삭제는 설정만 삭제합니다. 기존 저장 파일과 이력은 그대로 남습니다.

### 2. 기존 파일 인덱싱

이미 보관한 자료가 있다면 먼저 **5. 설정 · 중복 검사**에서 미분류 폴더와 추가 관리 폴더를 지정하고 **기존 파일 인덱싱 시작**을 누릅니다.

모든 범주 폴더·미분류 폴더·추가 관리 폴더의 위치, 크기, 수정 시간을 등록합니다. 파일을 이동하거나 삭제하지 않습니다. 크기가 같은 중복 후보가 생길 때 SHA-256을 스트리밍 방식으로 계산합니다. 권한이 없는 파일과 링크·정션 폴더는 처리되지 않을 수 있으며 결과에 접근 실패가 표시됩니다. 이후 기존 폴더에 파일을 수동으로 추가했다면 다시 인덱싱하세요.

### 3. 채팅방과 기간 선택

**1. 채팅방 선택 → 내 채팅방 불러오기**에서 여러 채팅방을 체크합니다. 채널 ID, `@username`, Telegram 링크를 쉼표로 추가 입력할 수도 있습니다.

- **과거 전체 이력**은 최근 500개로 제한하지 않고 Telegram의 페이지 조회를 끝까지 진행합니다.
- 전체 이력을 해제하면 채팅방당 최대 메시지 수를 지정합니다. 이 수는 파일 수가 아닌 메시지 수입니다.
- 기간은 한국 시간의 시작일 00:00부터 종료일 23:59:59까지입니다.
- 포럼 그룹은 **토픽 ID**를 지정하거나 `-100채널ID_토픽ID` / `https://t.me/c/채널ID/토픽ID` 형식을 사용할 수 있습니다.
- 조회 중 상태 표시로 검사한 메시지·발견한 파일 수를 확인하고 **조회 취소**로 멈출 수 있습니다. 이미 수집한 목록은 DB에 남습니다.
- 공개 채널과 현재 계정에 접근 권한이 있는 비공개 채팅만 지원합니다. 접근 제한을 우회하거나 채팅에 메시지를 쓰지 않습니다.

### 4. 형식 필터와 분류 미리보기

**2. 파일 · 분류 미리보기**에서 문서·동영상·이미지·오디오·압축·기타·확장자 없는 파일을 선택합니다. 추가 확장자를 입력하면 기본 분류에 없는 파일도 선택할 수 있습니다. 범주별 확장자 조건과 전체 다운로드 형식 필터는 별개입니다.

표에서 원본 파일명, 채팅방, 확장자, 크기, 범주, 적용 규칙·충돌, 저장 폴더, 중복 상태, 예상 상태, 최종 파일명을 확인합니다. 창보다 표가 넓으면 가로 스크롤을 사용하세요. 열 제목으로 정렬하고, 셀에 마우스를 올려 잘린 전체 내용을 확인할 수 있습니다.

**범주 셀을 두 번 클릭**하여 파일별로 범주를 바꾸면 경로가 즉시 바뀝니다. **자동 분류로 되돌리기**로 수동 지정을 해제합니다. 파일별 지정과 체크 상태는 저장됩니다.

파일을 내려받기 전에는 내용 중복을 확정할 수 없으므로 **내용 미확인**으로 표시합니다. Telegram 파일 이력이 있더라도 **파일 재검사 예정**이라고 표시하고, 실제 기존 파일의 SHA-256을 확인한 후 다운로드를 생략합니다.

**체크한 파일 다운로드**는 검색으로 숨겨진 체크도 포함합니다. 검색 결과만 받으려면 먼저 전체 체크를 해제한 뒤 검색하고 **표시된 파일 전체 선택**을 누르세요. 형식 필터로 제외된 파일은 받지 않습니다. 완료·중복 처리된 파일은 체크가 자동 해제됩니다.

### 5. 대기열, 중단, 재개

**4. 대기열 · 완료 파일**에서 파일별 진행률·속도, 이번 작업 전체 진행률, 완료·중복·실패 상태를 확인합니다.

- **전체 일시정지**: 받은 임시 데이터를 유지합니다.
- **일시정지 / 대기 재개**: 저장된 분류 경로와 중간 데이터를 사용합니다.
- **실패 파일 재시도**: 실패한 파일만 다시 처리합니다.
- 파일 행을 두 번 클릭하거나 **선택 파일 폴더 열기**로 실제 저장 폴더를 엽니다.
- 재시작 후 미완료 항목은 일시정지 상태로 복구되며, 사용자가 재개해야 다운로드합니다.
- 실행 중 규칙을 바꿔도 이미 대기열에 넣은 항목은 시작 시 확인한 경로를 유지합니다. 일시정지 후 미리보기에서 다시 선택해 넣으면 새 분류 계획을 적용합니다.

## 중복과 파일 보존 동작

1. 계정·채팅·메시지·미디어 순번·Telegram 파일 ID로 항목을 구별합니다. 다른 채팅의 같은 메시지 ID는 충돌하지 않습니다.
2. 같은 계정에서 받은 동일 Telegram 파일 이력을 찾고, 기존 파일의 크기와 SHA-256을 다시 확인하여 네트워크 다운로드를 생략합니다.
3. 새 파일은 대상 폴더의 `.tsd-staging` 안에 임시 저장합니다. 파일 크기와 다운로드 청크가 확인되기 전에는 완료로 기록하지 않습니다.
4. 받은 파일의 SHA-256을 계산하고 기존 다운로드·인덱싱된 파일 전체에서 같은 크기 후보를 비교합니다.
5. 내용이 같으면 기존 파일을 유지하고 새 임시 파일만 정리합니다. 이름이 같고 내용이 다르면 `파일명 (2).확장자`처럼 별도 저장합니다. 빈 기존 파일도 덮어쓰지 않습니다.
6. 최종 저장 경로, 선택한 범주, SHA-256, 중복 사유와 기존 위치를 SQLite 이력에 남깁니다.

분류는 처음부터 목적 폴더로 저장합니다. 이미 완료된 파일의 범주를 바꿔도 기존 파일을 자동 이동하거나 새 사본을 만들지 않습니다. 프로그램 밖에서 파일을 옮겼다면 새 위치를 인덱싱하세요. Telegram 이력에 연결된 예전 위치가 없어졌을 경우 한 번 다시 다운로드하여 내용 비교가 필요할 수 있지만, 인덱싱된 동일 내용의 추가 보관은 방지합니다.

## 데이터와 복구

- 새 EXE의 데이터 폴더: `%LOCALAPPDATA%\TelegramSmartDownloader`
- 개발 실행: 저장소 루트. 기존 EXE 옆에 `downloader.db`가 있는 휴대용 설치는 그 위치를 계속 사용합니다.
- `TSD_DATA_DIR` 환경 변수로 별도 데이터 폴더를 지정할 수 있습니다.
- `downloader.db`: 기존 테이블을 유지하고 `smart_*` 테이블을 추가합니다. 원본 JSON 마이그레이션도 유지합니다.
- `.env`, `.session`, DB와 설정은 Git에서 제외합니다. `.env.local`과 `config.json`의 원본 Git 추적은 해제하지만 로컬 파일은 보존합니다.
- 동일 데이터 폴더로 프로그램 두 개를 동시에 실행하지 않도록 잠급니다.

문제가 생겼다면 **대기열의 오류 내용**을 확인하고, 네트워크·디스크 여유 공간·저장 폴더 권한을 점검한 뒤 재시도하세요. Telegram 요청 제한은 서버가 지정한 시간만큼 기다립니다. 강제 종료 후에도 검증된 임시 청크를 재사용하며, 파일 저장 직후 DB 갱신 전에 종료된 경우에도 기록된 SHA-256으로 저장 결과를 복구합니다.

다운로드 중에는 `.tsd-staging` 또는 DB를 수동으로 지우지 마세요. 오류 로그에는 `crash_report.log`가 사용될 수 있습니다. 로그나 DB를 다른 사람에게 전달하기 전에 개인정보 포함 여부를 확인하세요.

## 테스트와 Windows EXE 빌드

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\build_windows.ps1
```

빌드 스크립트는 의존성 설치 → 자동 테스트 → PyInstaller 빌드 → EXE 오프라인 GUI 시작·종료 검증을 실행합니다. 결과는 `dist/TelegramSmartDownloader.exe`입니다. 이미 의존성과 테스트가 준비됐다면 `-SkipInstall -SkipTests` 옵션을 사용할 수 있습니다. 기존 원본 spec도 남겨 두었으며, 스마트 버전은 `TelegramSmartDownloader.spec`을 사용합니다. 빌드 결과와 중간 산출물은 `dist/`, `build/`로 소스와 분리됩니다.

빌드된 EXE만 다시 검사하려면 `.\tools\verify_exe.ps1`을 실행합니다. 매번 새 테스트 폴더를 만들고 실제 계정 연결 없이 창 생성·탭 구성·정상 종료를 확인합니다. 외부 도구가 PATH에 등록한 동명의 ICU DLL이 섞이지 않도록 spec에서 DLL 탐색 경로를 제한하고 Windows 시스템 ICU를 사용합니다.

EXE 오프라인 시작·종료 검증 예시:

```powershell
$env:TSD_DATA_DIR = Join-Path $PWD '.test-data\exe-smoke'
$env:QT_QPA_PLATFORM = 'offscreen'
$p = Start-Process '.\dist\TelegramSmartDownloader.exe' -ArgumentList '--smoke-test' -PassThru -Wait -WindowStyle Hidden
Get-Content '.test-data\exe-smoke\smoke-result.json'
Remove-Item Env:TSD_DATA_DIR, Env:QT_QPA_PLATFORM
```

이 모드는 Telegram 클라이언트를 시작하지 않습니다. 예시 화면 검증은 `python tools/qa_preview.py --output .test-data/visual-qa`로 재현합니다. GitHub에서는 **Smart Downloader Windows** 워크플로로 같은 테스트와 EXE 패키징을 실행할 수 있습니다.

## 검증 범위와 남은 확인 사항

- 자동 검증: 한글·대소문자·복수 키워드·Unicode·충돌·확장자·미분류·수동 지정, 계정/채팅 격리, 내용 중복 4가지 경우, 기존 인덱싱, 재시작, 실제 최종 위치 재사용, 중단·재개, 네트워크 재시도, FloodWait 대기, Windows 경로, 설정 복원, 25,000행 Qt 모델.
